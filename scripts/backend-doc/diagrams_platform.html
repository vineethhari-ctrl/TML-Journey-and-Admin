Sign-in: the checks the database makes

1 · TML SSO
The user proves who they are (password, OTP).Passwords and password expiry stay with SSO. The portal never sees a password.
➜
2 · Device
register_deviceKnown device: last seen refreshed.
New device: PENDING until a TML admin approves it (admins notified), or ACTIVE when approval is switched off.
Only a SHA-256 fingerprint is stored.
➜
3 · Checks
start_session refuses when:• the account is not ACTIVE (an automatic lock whose time has passed is lifted first)
• the device is PENDING, BLOCKED or INACTIVE, or belongs to someone else
LimitAbove the maximum concurrent sessions, the least recently used session ends (SUPERSEDED).
➜
4 · Session
ACTIVEEvery request calls touch_session: false = sign in again.
Sign-in recorded in login_attempt; last sign-in kept on the user.
Failed sign-in → record_login_failure: after N failures in a row (setting, default 5) the account is LOCKED for the lock duration (default 30 min); open sessions end, TML admins are notified, the audit gets a WARNING. A successful sign-in resets the count.

How a session ends (end_reason)

The user
LOGOUTSigning out also discards the session-only layout (BU decision 6 Oct 2026).
Time and limits
TIMEOUTIDLE_TIMEOUTSUPERSEDEDSession timeout (default 60 min), idle timeout (default 15 min, never longer than the session timeout), concurrent limit (default 3). Routine: not audited.
An admin
TERMINATED_BY_ADMINOne session, all of a user, all of a device, or everybody except the admin.
Audited: Session Terminated (All).
A change elsewhere
DEVICE_BLOCKEDDEVICE_DEACTIVATEDUSER_SUSPENDEDUSER_LOCKEDUSER_INACTIVEPASSWORD_CHANGEDEnded at once by the database itself. Audited: Sessions Ended.
An ended session is history: the database refuses to reopen or change it. Housekeeping removes ended sessions and sign-in attempts after the retention period (new setting, default 180 days).
